# Alpha Lab · Agent 投资实验室

> 原始 Windows 依赖快照仍保存在 requirements.lock.txt；本次 Linux/Docker 增加 cryptography 依赖，请使用 requirements.txt 安装。

> 本仓库已适配 GitHub Pages 前端 + 独立 Python 后端。预计前端地址：<https://usbfl.github.io/suiyi.github.io/>。完整部署步骤见 [GitHub Pages 部署说明](docs/GITHUB_PAGES.md)。行情、回测与 Agent 功能需连接后端。

每位选手拥有 **100 万元独立虚拟资金**，自主寻找股票、查资料、提出假设、买卖或等待，再依据实际账户反馈修订策略。

默认六位选手，可为每场实验配置 **1–8 位 Agent**。Agent 工作室可保存独立配置：名称、策略、模型连接、自定义模型名称、温度、输出长度、工具轮数和工具权限。默认连接使用 DeepSeek，也可配置兼容 Chat Completions 的服务；相同模型下的不同角色是**策略对照实验**，不冒充不同模型厂商。

六个默认 Agent 使用 deepseek-1 至 deepseek-6 代号，起始策略依次为价值、趋势、风控、逆向、轮动与策略实验。策略是可以编辑的起点，买卖行为仍由模型和真实工具反馈决定。

产品主流程是 **选择历史区间 → 学习与复盘 → 冻结策略验证 → 选择选手进入实时跟盘**。已经保存的三选手比赛仍可打开，历史账户与记录不重置。

首页是独立的**实时行情工作台**：默认每 30 秒检查腾讯财经报价，通过 SSE 自动更新股票价格、报价时间、自选列表与股票详情。即使当前打开已完成的历史回测，首页也读取最新行情；历史账户、日线边界和策略记录不受影响。可搜索沪深北 A 股并保存自选列表，切换实际日线与实时采样曲线。休市、数据延迟和行情源故障均保留原始报价时间；查看行情不触发模型决策。刷新间隔可在“运行参数”中配置，Agent 自主交易仍在“实时模拟”中开启。

```powershell

```


## 两种比赛

| | 历史回溯 | 实时跟盘 |
| --- | --- | --- |
| 时间 | 选择起止交易日，可指定验证起点；每轮前进一个交易日 | 真实北京时间 |
| 可见行情 | 回放日期及以前的日线 | 当前报价与已知历史日线 |
| 公司联网研究 | 禁止现时联网；可检索已归档且满足日期与历史可用性条件的资料 | 公司资料、官方公告、行业报告检索、来源阅读与证据归档 |
| 委托撮合 | 收盘后决策；后续交易日开盘价加模拟滑点尝试成交 | 委托之后的新报价，满足连续竞价时段、时效、限价等条件才撮合 |
| 自主运行 | 连续完成所选区间，可暂停、继续，到结束日自动停止 | 开启后，持续监测价格，达到波动或时间条件触发模型决策 |
| 策略迭代 | 学习期更新策略；验证期冻结策略与笔记，只观察执行表现 | 使用带历史来源的策略开始，再根据实时反馈继续迭代 |

实时模式默认每 30 秒尝试刷新已观察股票的报价。开启自主跟盘后，默认距上次决策至少 60 秒且任一已观察标的累计波动达到 0.6%，或距上次决策达到 15 分钟，会触发一轮决策。这些时间与波动参数可配置，并保存到新实验的配置快照。休市不自动调用模型，但用户可以手动让选手研究与提交委托。
自动跟盘需要本地服务持续运行，不是云端托管任务。服务重启后恢复账户，但自动跟盘保持关闭。

历史回溯首轮在所选日期收盘状态决策，第二轮先推进至下一交易日并撮合旧订单，然后公布当日收盘状态供 Agent 决策。新订单绝不会回到已知的当日收盘价立即成交。

## 不限定股票名单

系统**没有固定股票白名单**。默认显示的 8 只股票只是起始观察列表。
选手可以扫描全市场当前榜单，按名称/代码搜索沪、深、北 A 股，并按需下载任何有效证券的历史行情，加入自己的研究与交易。

支持主板、创业板、科创板和北交所的普通申报数量差异。数据接口无法返回的标的、停牌日、早于上市的日期等会明确失败，不会用生成价格凑数。
未覆盖所有特殊证券状态和全部交易所制度；可发现证券不等于所有时候都能可靠模拟成交。ETF、B 股、港美股和衍生品不属于本次 A 股比赛范围。

## Agent 实际能做什么

模型使用多轮工具调用，自行选择顺序和停止时机；不是一次生成一份建议列表再由前端播放。

| 工具 | 作用 |
| --- | --- |
| `get_account` | 读取现金、可用资金、持仓和未完成委托 |
| `market_scan` | 实时全市场成交活跃、涨幅、跌幅榜；回放仅显示当时已加载的行情 |
| `stock_search` | 按代码/名称发现 A 股，不返回现时价格 |
| `price_history` | 获取不晚于当前比赛日期的日线，按需扩展股票范围 |
| `company_profile` | 通过公开接口查询公司主营业务与简介 |
| `search_web` | 自主查询 Bing RSS 搜索结果，保留标题、摘要、来源链接和获取时间 |
| `read_source` | 读取本轮搜索来源中的允许网站正文或 PDF，正文分块归档；12 MB、最多前 40 页、18 万字符 |
| `search_company_filings` | 从巨潮资讯检索公司公告与定期报告，返回官方来源与公告日期 |
| `search_industry_reports` | 检索公开行业资料，保留可读性与来源信息 |
| `company_financials` | 查询第三方当前利润表摘要，明确报告期、营业收入、归母净利润及人民币元单位；历史模式禁用 |
| `search_evidence` / `read_evidence` | 搜索和读取本地资料分块；历史模式同时校验发布日期与时点依据 |
| `save_research_note` | 将研究结论绑定到文档、分块和连续原文引用；伪造引文会被后端拒绝 |
| `place_order` / `cancel_order` | 提交限价委托、主动撤单；执行结果由交易引擎决定 |
| `save_note` | 保存个人研究假设、风险或下一轮要核实的问题 |
| `finish` | 总结本轮行为、风险、教训和下一版策略 |

每位选手默认每轮最多 7 次模型决策，可配置为 2–12 次；每次最多执行 4 个工具、每轮最多 4 次订单修改。每位 Agent 的工具权限会同时约束提供给模型的工具清单与后端实际执行；`finish` 与 `get_account` 是必要工具。上限控制成本与副作用，不决定买哪只股票。
最后一次决策只开放复盘工具。失败与非法工具会记录，不能让模型声称成功就算成交。
界面显示的是公开理由、工具输入与返回，不展示内部思维链。

## 如何“自适应迭代”

每轮环境先给出上一轮委托的实际结果与当前净值，再把账户历史、最大回撤、私有研究笔记及上轮策略带给模型。
模型自主输出 `lesson` 与 `next_strategy`，形成 V1、V2……版本。下一轮系统提示中会带入该选手自己的最新策略。

这是**基于反馈的上下文与记忆迭代**，不是修改模型权重、强化学习训练，也不保证收益持续增加。

### 从历史经验进入实时跟盘

1. 新建历史实验，选择开始日、结束日与可选的验证起点，配置参与的 Agent。日期必须来自已加载的真实交易日。
2. 学习期逐日执行：撮合上一日委托、计算账户反馈、研究和决策、记录教训与下一版策略。自动运行会推进整个区间，不再限制为三轮；仍受模型调用预算约束。
3. 首个验证交易日开始前，保存学习期的策略检查点。验证期不允许修改持久策略或研究笔记；账户、交易和公开说明继续更新，便于观察同一策略在后续区间的表现。
4. 所选区间完成后，选中有实际策略复盘记录的 Agent，创建实时比赛。仅转移策略经验、笔记与来源记录；每位重新获得 100 万元，清空历史持仓、委托与实盘统计。历史比赛保留，可以回看学习过程。

系统分别展示学习与验证表现，经验包记录训练区间、验证区间、来源比赛、源策略版本和迁移时间。没有验证期、验证天数过少或没有成交时，会提示证据不足。模型失败、没有产生策略版本的选手不能以“已学习”的状态迁移。
当前“已有独立验证样本”要求完成全区间、至少 5 个验证交易日与 5 次成功的验证复盘，且验证期至少有 1 笔成交。仅日期推进但模型持续失败，不会得到该标签。这是证据可用性门槛，不是盈利或稳定性评级。

“完成验证”只表示经过一个未用于修改策略的后续区间；它不是金融统计上的稳定性证明。少量交易、重复使用同一验证集挑选策略、预训练知识与行情局限仍会影响结果。实时阶段可继续更新策略，原始学习检查点保留为来源证据。

## 可配置参数与资金规则

运行设置可配置单股仓位上限、模拟滑点、佣金费率、最低佣金、行情刷新间隔、定时决策间隔、最短决策间隔与波动触发阈值。参数在创建实验或迁移到实时比赛时保存为 `runtime_settings`；后续编辑全局设置只影响新实验，已有比赛不会中途更换计费或风控规则。下面列出默认值。

- 每位初始资金 1,000,000 元；独立现金、持仓批次、委托和策略记忆。
- 账本使用整数“分”，模型工具接口统一使用“元”；测试覆盖这条转换边界。
- 股票买入后按交易日期进行 T+1 可卖判断，不允许卖空、融资、超额使用冻结资金。
- 主板/创业板一般从 100 股起、按 100 股递增；科创板从 200 股起、按 1 股递增；北交所从 100 股起、按 1 股递增。不足起点的剩余持仓需一次卖出。
- 单票最多 45% 为**本比赛的风控规则**，不是交易所对普通个人账户的统一要求。
- 模拟费用：双向佣金成交额 0.03%，最低 5 元；卖出印花税 0.05%；双向模拟过户费 0.001%。这些是比赛参数，不代表具体券商报价或全部法定费用。
- 模拟滑点为买入加 0.05%、卖出减 0.05%；滑点后的价格仍必须满足限价。
- 实时仅模拟连续竞价时段；集合竞价、盘后固定价格、大宗交易均不撮合。
- 实时价格必须来自委托之后、当天且距当前时间不超过 120 秒。旧报价不会“立即成交”。
- 保守地不假设涨停可买入、跌停可卖出。历史涨跌停价按普通板块规则估算；新股、ST、重新上市、除权等特殊情形并非完整实现。
- 不模拟真实盘口队列、部分成交、市场冲击或大额委托流动性。

沪深300为价格指数基准，比赛净值为现金加按报价计价的股票。当前未处理现金分红、送转配股与其他公司行为，所以展示的是简化价格路径实验，**不是含分红的总回报金融回测**。

## 行情从哪里来

| 数据 | 当前实现 | 限制 |
| --- | --- | --- |
| 日线 | 腾讯财经公开 K 线接口 | 不复权，默认最近 120 根；新证券按需加载；缓存保留来源和抓取时间 |
| 最新报价 | 腾讯财经公开行情接口 | 非交易所授权逐笔数据；可能延迟/停服；界面展示报价时刻 |
| 全市场榜单 | 东方财富公开行情接口 | 当前数据，只能用于实时模式 |
| 证券搜索 | 腾讯公开证券搜索 | 当前目录不是完整历史证券池，存在幸存者偏差 |
| 公司档案 | 东方财富公开公司档案接口 | 当前介绍，不是历史时点财务数据库 |
| 网页研究 | Bing RSS + 允许财经网站/官网原文 | 摘要可能不完整、发布日期可能缺失、网站可能拒绝抓取 |
| 官方公司公告 | 巨潮证券目录与公告索引、固定 PDF 原文 | 公告日期与报告期分开；PDF 需可读取，日期一致性校验不等于完整历史公告库 |
| 行业研究 | 近期券商目录、政府网站搜索与统计发布目录 | 券商目录仅最近 90 天最新 200 份；PDF 可能反爬、搜索可能为空，不是完整行业数据库 |
| 财务摘要 | 东方财富公开利润表接口 | 累计报告期口径，可能经历史更正，归档后仍默认不可用于历史回放 |

接口地址与解码逻辑集中在 `app/market.py`、`app/research.py`。没有依赖生成的股票价格。数据服务失败时使用明确带时间戳的本地缓存，首次完全无数据则报错。
公开可访问不等于有再分发授权或服务保障；当前仅用于本地工程原型，正式商业/公开部署需要确认行情许可与供应商服务条款。

历史防未来信息：禁止现时网页、公司现时资料与现时排行榜；历史价格严格截断到比赛日；上市前无数据的股票不能成交。资料归档记录正文哈希、来源、抓取时刻、发布日期、分块及历史可用性依据。历史检索、直接读取和引用校验使用相同的日期边界：未知日期、晚于比赛日、没有明确历史可用性依据的资料均不可进入历史观察。

巨潮官方固定公告可保存其公告日期作为时点依据；普通网页即使含一个旧的 RSS 发布日期，也不能据此证明今天抓到的正文当年已经存在。手工导入资料的历史可用声明是用户提供的来源说明，不是系统对文件真实性的独立认证。当前采用日级日期边界，没有构建完整的公告秒级发布时间和修订版本数据库。

证据检索使用透明的关键词与中文双字匹配，返回相关文本块，不依赖向量模型。带引用的研究笔记要求 `document_id`、`chunk_id` 和该分块中的连续原文，最多 8 条引用；原文匹配证明可追溯性，不能证明模型对原文的解释正确。验证期也禁止新增持久研究笔记。
研究工作台还可导入有权使用的原文文本或可搜索 PDF，并填写发布日期与来源依据；扫描版 PDF 未包含可提取文字时会报错，本版没有 OCR。工具测试是独立研究操作，不调用模型或修改账户；读取原文会归档，保存 Agent 研究笔记只能在比赛工具流程内进行。
仍然存在模型预训练知识、当前证券目录、有限历史数据、忽略分红等偏差，因此不能声称结果是无偏回测或可靠选股依据。

## 模型配置与费用

可以在界面配置模型连接与 Agent，或首次启动时用 `.env.example` 创建本地 `.env`。默认连接只在当前数据库尚未创建时导入环境配置，后续以界面的连接设置为准；`.env` 被 `.gitignore` 排除。

连接包含名称、适配器、服务地址、可选模型列表与密钥。普通服务使用 HTTPS，本机服务可使用 localhost / 127.0.0.1 的 HTTP 地址。模型名可以手动填写，`/models` 连通性检查只读取模型列表，不代表生成、工具调用和所有参数都已兼容。
服务地址填写完整 API 基址；需要 `/v1` 的提供商应包含这一段，应用会追加 `/chat/completions` 或 `/models`。连接编辑在下一轮生效，同一 Agent 已开始的工具循环固定使用本轮连接快照。

密钥使用 **Windows 当前用户 DPAPI** 加密后存入 SQLite，不提供明文存储降级。连接 API 只返回是否已配置密钥；空密钥更新表示保留，显式清除才删除。密钥不进入 Agent 配置、比赛快照或导出。该保险箱绑定当前 Windows 用户环境，复制数据库到其他用户或系统后可能需要重新配置连接。API 工具记录仍可能包含研究内容，应按自己的数据分享范围导出。

模型观察包含行情、自己的模拟账户、研究结果与策略笔记，并发送给该 Agent 选择的模型服务。不同连接的密钥和参数按调用隔离，模型本身不能修改连接或读取保险箱。

```dotenv
LLM_BASE_URL=https://api.deepseek.com
LLM_API_KEY=填写你自己的密钥
LLM_MODEL=deepseek-flash
LLM_TIMEOUT=45
LLM_CONCURRENCY=3
LLM_MAX_CALLS=300
```

实际模型由每位选手的比赛配置决定。DeepSeek 适配器使用非思考模式；通用适配器发送 Chat Completions 工具调用请求，不附加 DeepSeek 专用字段。temperature、max_tokens 与工具轮数直接参与请求和执行，不只是界面展示。不同服务对这些字段、`tool_choice` 和模型名称的支持可能不同，尚未逐家进行真实服务兼容性验证。
最大调用数为当前服务进程级预算，包括失败请求；重启会重置。Token 从服务返回值累计，缺失 usage 不代表免费。
每轮研究次数和上下文长度不同，费用不固定。模型失败不会偷偷切换成硬编码炒股策略。
历史区间较长时，系统会显示预计调用上限。启动下一轮前按参与选手各自的工具轮数预留调用预算；不足时保留进度并暂停。可追加调用额度后继续，不需要重建实验。该额度是请求次数上限，不是人民币费用承诺。

## 后端实现

```text
app/market.py    行情、股票发现、数据时间边界
app/market_monitor.py  独立实时首页、TTL、自选列表、原始报价采样
app/research.py  网页搜索、来源 ID、原文提取与访问边界
app/evidence.py  原文分块、来源哈希、日级时点校验与连续引文校验
app/research_tools.py  公司公告、行业资料、证据与研究笔记工具
app/configuration.py  模型连接、可复用 Agent 配置、运行参数与校验
app/secrets.py   当前 Windows 用户 DPAPI 保险箱
app/broker.py    整数资金账本、冻结、T+1、限价、费用与撮合
app/agent.py     有界工具循环、模型并发、Token 与预算
app/engine.py    多账户隔离、区间学习、冻结验证、经验迁移、原子提交与恢复
app/main.py      FastAPI REST / SSE / 导出 / 比赛存档 / 策略配置
static/         实验工作台、净值比较、验证进度、经验库与实时跟盘
```

并发 Agent 只修改本轮各自的工作账户，轮次完成后在同一个 SQLite 事务提交账户、快照和请求幂等记录。
工具审计过程实时落库，最终标记为已提交或已回滚；崩溃遗留的过程记录在重启时标记为 interrupted。
SSE 发送完整当前状态，断线后重新同步。自动行情刷新不额外创建完整历史快照，仅保存当前可恢复状态；Agent 决策轮保留快照。
这是单机单用户原型，进程锁不是跨实例分布式锁，不能用多 worker 直接扩容。

```powershell
./.venv/Scripts/python.exe -m pytest -q
```

浏览器测试先在一个终端启动 8011 隔离服务：

```powershell
./.venv/Scripts/python.exe tests/browser_server.py
```

另一个终端执行：

```powershell
npm ci
npm run test:browser
```

默认浏览器流程只连接明确标记的隔离服务，使用系统临时数据库、合成测试行情与模拟策略，不调用真实模型或写入 8010 的本机数据。覆盖历史学习/验证/迁移、连接与 Agent 配置、证据管理、独立实时行情。测试结束后关闭隔离服务，临时数据随服务退出清理。

`browser-visual.cjs` 是展示服务只读验收，需要已有完成回测；`browser-research-live.cjs` 会归档实际资料，不属于默认隔离测试。旧 `browser.cjs` 不再作为新版默认入口。
